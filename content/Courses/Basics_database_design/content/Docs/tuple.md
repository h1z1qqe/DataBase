# Понятие кортежа: от теории множеств к базам данных

**Кортеж (tuple)** — одно из центральных понятий, которое пришло в базы данных из математики. Разберём его на трёх уровнях: математическом, реляционном и практическом (SQL).

---

## 🔹 1. Кортеж в математике

**Определение:** Кортеж — это **упорядоченный набор элементов фиксированной длины**.

Обозначается в круглых скобках:

```
(1, 'Иван', 'Москва')
(120, 200, 350)
('Яблоки', 120)
```

**Ключевые свойства математического кортежа:**

| Свойство | Что означает | Пример |
|----------|--------------|--------|
| **Упорядоченность** | Порядок элементов важен | `(1, 2) ≠ (2, 1)` |
| **Фиксированная длина** | Количество элементов задано | Кортеж из 3 элементов нельзя «удлинить» |
| **Элементы могут повторяться** | В отличие от множества | `(1, 1, 2)` — допустимый кортеж |
| **Элементы могут быть разных типов** | Не обязаны быть однородными | `('Иван', 25, true)` |

**Важно:** кортеж — это **не множество**. В множестве `{1, 2}` порядок не важен и дубликаты невозможны. В кортеже `(1, 2)` порядок задан жёстко, а `(1, 1)` — допустим.

**Частные случаи кортежа:**
- Кортеж длины 2 — **пара** (упорядоченная пара).
- Кортеж длины 3 — **тройка**.
- Кортеж длины n — **n-ка**.

## 🔹 2. Кортеж в реляционной модели

В реляционной модели **строка таблицы = кортеж**.

**Определение:** Кортеж — это **элемент отношения** (таблицы), то есть одна строка, состоящая из набора значений атрибутов.

**Пример:** таблица `customers`

| id | name | city |
|----|------|------|
| 1 | Иван Иванов | Москва |
| 2 | Пётр Петров | Санкт-Петербург |
| 3 | Мария Сидорова | Москва |

Здесь:
- Вся таблица — это **множество кортежей** (отношение).
- Строка `(1, 'Иван Иванов', 'Москва')` — **один кортеж**.
- Строка `(2, 'Пётр Петров', 'Санкт-Петербург')` — **другой кортеж**.

**Соответствие терминов:**

| Реляционная модель | Теория множеств | SQL | Бытовое |
|--------------------|-----------------|-----|---------|
| Отношение | Множество кортежей | Таблица | Таблица |
| Кортеж | Элемент множества | Строка (row) | Строка |
| Атрибут | Координата кортежа | Столбец (column) | Столбец |
| Степень отношения | Длина кортежа | Число столбцов | — |
| Кардинальность | Число кортежей | Число строк | — |

## 🔹 3. Почему «кортеж», а не «строка»?

Это не просто терминологическая прихоть. Разница принципиальная:

### Строка в файле / CSV
- Имеет **порядок** (первая строка, вторая строка).
- Может содержать **дубликаты** (две одинаковые строки — нормально).
- Позиция важна: «строка №5».

### Кортеж в реляционной модели
- **Не имеет порядка** — множество кортежей неупорядочено. Именно поэтому в SQL без `ORDER BY` порядок строк **не гарантирован**.
- **Не может дублироваться** в рамках одного отношения — иначе это не множество. Именно поэтому существует `PRIMARY KEY` и `DISTINCT`.
- **Имеет фиксированную структуру** — набор атрибутов задан схемой отношения.

**Пример:** если вы выполните

```sql
SELECT * FROM customers;
```

дважды подряд, порядок строк может быть **разным**. Это не баг, а следствие того, что таблица — это множество кортежей, а множество неупорядочено.

## 🔹 4. Кортеж и NULL

Здесь есть тонкость. Если кортеж — это элемент множества, а `NULL` — это «отсутствие значения», то кортеж с `NULL` — это кортеж с «дыркой».

**Пример:** таблица `customers` с NULL в поле `city`:

| id | name | city |
|----|------|------|
| 1 | Иван Иванов | Москва |
| 2 | Пётр Петров | **NULL** |

Кортеж `(2, 'Пётр Петров', NULL)` — это **полноценный элемент множества**. Он существует. Но его координата `city` **неизвестна**.

Именно отсюда растут все «странности» `NULL`:
- `NULL = NULL` → `NULL` (не `TRUE`), потому что неизвестное не равно неизвестному.
- `COUNT(city)` не считает `NULL`-кортежи, потому что считает **известные** значения.
- `NOT IN` с `NULL` в списке → пустой результат, потому что сравнение с неизвестным даёт «неизвестно».

## 🔹 5. Кортеж и функциональные зависимости

Функциональная зависимость `X → Y` формулируется **в терминах кортежей**:

> Если два кортежа `t1` и `t2` совпадают по атрибутам множества `X`, то они совпадают и по атрибутам множества `Y`.

**Пример:** в таблице `customers` зависимость `id → name` означает:

```
Если t1.id = t2.id, то t1.name = t2.name
```

То есть одинаковый `id` гарантирует одинаковое `name`. Это и есть функциональная зависимость — свойство **множества кортежей**, а не отдельных строк.

Именно через кортежи определяется:
- **Первичный ключ** — минимальный набор атрибутов, который уникально идентифицирует кортеж.
- **Нормальные формы** — условия на множество кортежей, при которых нет аномалий.
- **Целостность сущностей** — каждый кортеж должен быть идентифицируем.

## 🔹 6. Кортеж в SQL: практические следствия

Понимание того, что строка — это кортеж (элемент множества), объясняет многие правила SQL:

### 6.1. Почему `DISTINCT` существует
Потому что множество не содержит дубликатов. Если в таблице появились две одинаковые строки — это уже не отношение (нарушение реляционной модели). `DISTINCT` возвращает таблицу к «множественному» виду.

### 6.2. Почему `ORDER BY` нужен явно
Потому что множество неупорядочено. Без `ORDER BY` СУБД вправе вернуть кортежи в любом порядке.

### 6.3. Почему `PRIMARY KEY` обязателен
Потому что каждый кортеж должен быть уникален и идентифицируем. Без ключа невозможно отличить один кортеж от другого.

### 6.4. Почему `EXCEPT` / `UNION` работают как множества
Потому что они оперируют **множествами кортежей**:
- `UNION` — объединение множеств (дубликаты удаляются).
- `UNION ALL` — работа с мультимножеством (дубликаты сохраняются).
- `EXCEPT` — разность множеств кортежей.

### 6.5. Почему `INSERT` добавляет кортеж
Каждая команда `INSERT` добавляет **один кортеж** в отношение. Если нарушается `PRIMARY KEY` или `UNIQUE` — СУБД отказывает, потому что множество не может содержать дубликат.

## 🔹 7. Сравнение: множество vs кортеж vs отношение

| Понятие | Порядок | Дубликаты | Пример |
|---------|---------|-----------|--------|
| **Множество** | Не важен | Запрещены | `{1, 2, 3}` |
| **Кортеж** | Важен | Разрешены | `(1, 2, 3)` |
| **Отношение (таблица)** | Не важен (между кортежами) | Запрещены (между кортежами) | Таблица `customers` |
| **Мультимножество** | Не важен | Разрешены | Результат `UNION ALL` |

**Тонкость:** отношение — это **множество кортежей**. Внутри одного кортежа порядок атрибутов важен (это координаты), но между кортежами порядка нет.

## 🔹 8. Пример: разбор одного кортежа

Возьмём таблицу `orders`:

| id | customer_id | order_date | amount | status |
|----|-------------|------------|--------|--------|
| 1 | 1 | 2026-10-01 | 1500.00 | paid |

Один кортеж:

```
(1, 1, '2026-10-01', 1500.00, 'paid')
```

**Разбор по координатам:**

| Позиция | Атрибут | Значение | Домен |
|---------|---------|----------|-------|
| 1 | id | 1 | INT |
| 2 | customer_id | 1 | INT |
| 3 | order_date | 2026-10-01 | DATE |
| 4 | amount | 1500.00 | DECIMAL(10,2) |
| 5 | status | paid | VARCHAR(20) |

Каждая координата принадлежит своему **домену** (множеству допустимых значений). Кортеж — это точка в декартовом произведении доменов:

```
D(id) × D(customer_id) × D(order_date) × D(amount) × D(status)
```

Именно поэтому отношение иногда определяют как **подмножество декартова произведения доменов**:

```
orders ⊆ D(id) × D(customer_id) × D(order_date) × D(amount) × D(status)
```

Это уже чистая теория множеств: таблица — это множество точек в многомерном пространстве, где каждая ось — это домен атрибута.

## 🔹 9. Итоговая схема

```
Теория множеств                    Реляционная модель
─────────────────                  ──────────────────
Множество          ───────────►    Отношение (таблица)
Элемент множества  ───────────►    Кортеж (строка)
Координата         ───────────►    Атрибут (столбец)
Декартово произв.  ───────────►    Схема отношения
Подмножество       ───────────►    Экземпляр отношения
```

## 📌 Ключевая мысль

**Кортеж — это «строка, которая знает своё место в теории множеств».**

- В математике кортеж — упорядоченный набор значений.
- В БД кортеж — элемент множества строк (отношения).
- В SQL кортеж — это строка, но с важными оговорками: она не имеет порядка среди других строк, не может дублироваться и имеет фиксированную структуру атрибутов.

Когда вы понимаете, что таблица — это **множество кортежей**, становятся логичными:
- `DISTINCT` (убрать дубликаты),
- `ORDER BY` (навязать порядок множеству),
- `PRIMARY KEY` (идентифицировать кортеж),
- `EXCEPT` / `UNION` (операции над множествами кортежей),
- `NULL` (кортеж с неизвестной координатой),
- нормализация (разбиение множества кортежей на подмножества без аномалий).
