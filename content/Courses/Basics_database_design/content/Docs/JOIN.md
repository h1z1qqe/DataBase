# JOIN в SQL — подробное руководство

`JOIN` — это оператор, который **соединяет строки из двух или более таблиц** на основе общего столбца (обычно это первичный ключ одной таблицы и внешний ключ другой). Без `JOIN` работать с реляционными базами данных практически невозможно: данные намеренно разнесены по таблицам, чтобы избежать дублирования.

---

## 🔹 Зачем нужен JOIN

Представьте, что у вас есть две таблицы:

**customers:**
| id | name | city |
|----|------|------|
| 1 | Иван Иванов | Москва |
| 2 | Пётр Петров | Санкт-Петербург |
| 3 | Мария Сидорова | Москва |
| 4 | Алексей Смирнов | Казань |
| 5 | Ольга Кузнецова | Новосибирск |

**orders:**
| id | customer_id | order_date | amount | status |
|----|-------------|------------|--------|--------|
| 1 | 1 | 2026-10-01 | 1500.00 | paid |
| 2 | 1 | 2026-10-05 | 2300.50 | paid |
| 3 | 2 | 2026-10-03 | 800.00 | new |
| 4 | 3 | 2026-10-07 | 4200.00 | paid |
| 5 | 3 | 2026-10-10 | 1100.00 | cancelled |
| 6 | 4 | 2026-10-12 | 950.00 | new |

В таблице `orders` хранится только `customer_id` — число. Чтобы узнать **имя** клиента, нужно соединить таблицы через `JOIN`.

---

## 🔹 Синтаксис JOIN

```sql
SELECT столбцы
FROM таблица1
JOIN таблица2 ON условие_соединения;
```

- `таблица1` — главная (левая) таблица.
- `таблица2` — присоединяемая (правая) таблица.
- `ON` — условие, по которому строки считаются совпадающими. Обычно это `левая.id = правая.внешний_ключ`.

---

## 🔹 Основные типы JOIN

### 1. INNER JOIN (внутреннее соединение)

**Что делает:** возвращает только те строки, для которых **есть совпадение в обеих таблицах**.

**Синтаксис:**
```sql
SELECT c.name, o.order_date, o.amount
FROM customers c
INNER JOIN orders o ON c.id = o.customer_id;
```

**Результат:**
| name | order_date | amount |
|------|------------|--------|
| Иван Иванов | 2026-10-01 | 1500.00 |
| Иван Иванов | 2026-10-05 | 2300.50 |
| Пётр Петров | 2026-10-03 | 800.00 |
| Мария Сидорова | 2026-10-07 | 4200.00 |
| Мария Сидорова | 2026-10-10 | 1100.00 |
| Алексей Смирнов | 2026-10-12 | 950.00 |

**Кто не попал:** Ольга Кузнецова (у неё нет заказов).

**Важно:** `INNER JOIN` и просто `JOIN` — это одно и то же. Слово `INNER` можно опускать.

---

### 2. LEFT JOIN (левое внешнее соединение)

**Что делает:** возвращает **все строки из левой таблицы**, даже если нет совпадений в правой. Для несовпавших строк правая таблица даёт `NULL`.

**Синтаксис:**
```sql
SELECT c.name, o.order_date, o.amount
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id;
```

**Результат:**
| name | order_date | amount |
|------|------------|--------|
| Иван Иванов | 2026-10-01 | 1500.00 |
| Иван Иванов | 2026-10-05 | 2300.50 |
| Пётр Петров | 2026-10-03 | 800.00 |
| Мария Сидорова | 2026-10-07 | 4200.00 |
| Мария Сидорова | 2026-10-10 | 1100.00 |
| Алексей Смирнов | 2026-10-12 | 950.00 |
| **Ольга Кузнецова** | **NULL** | **NULL** |

**Когда использовать:**
- Нужно показать всех клиентов, включая тех, кто ничего не заказал.
- Нужно найти «сирот» — клиентов без заказов:
  ```sql
  SELECT c.name FROM customers c
  LEFT JOIN orders o ON c.id = o.customer_id
  WHERE o.id IS NULL;
  ```

**Альтернативный синтаксис:** `LEFT OUTER JOIN` — то же самое.

---

### 3. RIGHT JOIN (правое внешнее соединение)

**Что делает:** возвращает **все строки из правой таблицы**, даже если нет совпадений в левой.

**Синтаксис:**
```sql
SELECT c.name, o.order_date, o.amount
FROM customers c
RIGHT JOIN orders o ON c.id = o.customer_id;
```

**Результат:** то же, что и `LEFT JOIN`, только «главной» считается таблица `orders`. Если бы в `orders` был заказ с `customer_id`, которого нет в `customers` (нарушение ссылочной целостности), он бы попал в результат с `NULL` в имени клиента.

**На практике:** `RIGHT JOIN` используется редко. Почти всегда его можно переписать как `LEFT JOIN`, поменяв таблицы местами:

```sql
-- Эквивалент RIGHT JOIN
SELECT c.name, o.order_date, o.amount
FROM orders o
LEFT JOIN customers c ON o.customer_id = c.id;
```

---

### 4. FULL JOIN (полное внешнее соединение)

**Что делает:** возвращает **все строки из обеих таблиц**. Если нет совпадения — с соответствующей стороны будет `NULL`.

**Синтаксис:**
```sql
SELECT c.name, o.order_date, o.amount
FROM customers c
FULL JOIN orders o ON c.id = o.customer_id;
```

**Результат:** все клиенты + все заказы. Ольга Кузнецова будет с `NULL` в заказах, а если бы был заказ без клиента — он был бы с `NULL` в имени.

⚠️ **Важно:** MySQL **не поддерживает** `FULL JOIN` напрямую. Его эмулируют через `UNION`:

```sql
SELECT c.name, o.order_date, o.amount
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
UNION
SELECT c.name, o.order_date, o.amount
FROM customers c
RIGHT JOIN orders o ON c.id = o.customer_id;
```

PostgreSQL, SQL Server, Oracle — поддерживают `FULL JOIN`.

---

### 5. CROSS JOIN (декартово произведение)

**Что делает:** соединяет **каждую строку левой таблицы с каждой строкой правой**. Условие `ON` не используется.

**Синтаксис:**
```sql
SELECT c.name, o.id
FROM customers c
CROSS JOIN orders o;
```

**Результат:** 5 клиентов × 6 заказов = 30 строк.

**Когда использовать:**
- Генерация всех возможных комбинаций (например, все размеры × все цвета).
- Тестирование.
- Крайне редко в реальных задачах — легко получить миллионы строк.

**Эквивалент:**
```sql
SELECT c.name, o.id FROM customers c, orders o;  -- без WHERE
```

---

### 6. SELF JOIN (соединение таблицы с самой собой)

**Что делает:** таблица соединяется сама с собой. Используется для иерархических данных (сотрудник → руководитель, категория → родительская категория).

**Пример:** таблица `employees` с полем `manager_id`, ссылающимся на `id` в той же таблице.

```sql
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
```

**Важно:** обязательно нужны **разные алиасы** (`e` и `m`), иначе СУБД не поймёт, о какой таблице речь.

---

## 🔹 Сравнительная таблица

| Тип JOIN | Что возвращает | NULL с левой стороны | NULL с правой стороны |
|----------|----------------|----------------------|------------------------|
| `INNER JOIN` | Только совпадения | ❌ | ❌ |
| `LEFT JOIN` | Все строки левой + совпадения | ❌ | ✅ |
| `RIGHT JOIN` | Все строки правой + совпадения | ✅ | ❌ |
| `FULL JOIN` | Все строки обеих | ✅ | ✅ |
| `CROSS JOIN` | Декартово произведение | ❌ | ❌ |

**Мнемоника:** «LEFT JOIN — левая таблица главная, она вся в результате. RIGHT JOIN — правая главная.»

## 🔹 JOIN с несколькими таблицами

Можно соединять три и более таблиц. Пример: добавим таблицу `products` и `order_items`.

```sql
SELECT c.name, o.order_date, p.title, oi.quantity
FROM customers c
JOIN orders o ON c.id = o.customer_id
JOIN order_items oi ON o.id = oi.order_id
JOIN products p ON oi.product_id = p.id
WHERE o.status = 'paid';
```

СУБД выполняет соединения последовательно: сначала `customers + orders`, потом результат + `order_items`, потом + `products`.

## 🔹 JOIN и GROUP BY

Частый паттерн: соединить таблицы и посчитать агрегаты.

```sql
SELECT c.name,
       COUNT(o.id) AS order_count,
       SUM(o.amount) AS total_amount
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
GROUP BY c.id, c.name
ORDER BY total_amount DESC;
```

Обратите внимание на `LEFT JOIN` — он позволяет включить клиентов без заказов. Тогда:
- `COUNT(o.id)` вернёт `0` (потому что `o.id` = NULL, а `COUNT` игнорирует NULL).
- `SUM(o.amount)` вернёт `NULL` (нужно обернуть в `COALESCE(SUM(o.amount), 0)`).

**Результат:**
| name | order_count | total_amount |
|------|-------------|--------------|
| Мария Сидорова | 2 | 5300.00 |
| Иван Иванов | 2 | 3800.50 |
| Алексей Смирнов | 1 | 950.00 |
| Пётр Петров | 1 | 800.00 |
| Ольга Кузнецова | 0 | NULL |

Чтобы вместо `NULL` был `0`:

```sql
SELECT c.name,
       COUNT(o.id) AS order_count,
       COALESCE(SUM(o.amount), 0) AS total_amount
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
GROUP BY c.id, c.name
ORDER BY total_amount DESC;
```

## 🔹 JOIN vs подзапрос

Иногда один и тот же результат можно получить и через `JOIN`, и через подзапрос.

**Через JOIN:**
```sql
SELECT DISTINCT c.name
FROM customers c
JOIN orders o ON c.id = o.customer_id
WHERE o.amount > 1000;
```

**Через IN:**
```sql
SELECT name FROM customers
WHERE id IN (SELECT customer_id FROM orders WHERE amount > 1000);
```

**Через EXISTS:**
```sql
SELECT name FROM customers c
WHERE EXISTS (
    SELECT 1 FROM orders o
    WHERE o.customer_id = c.id AND o.amount > 1000
);
```

**Что выбрать:**
- Если нужны данные из обеих таблиц — `JOIN`.
- Если нужно только проверить наличие — `EXISTS` (часто быстрее).
- Если нужен список ID — `IN`.

## 🔹 Типичные ошибки

### 1. Забыли условие ON → CROSS JOIN
```sql
-- Вернёт 30 строк вместо 6!
SELECT * FROM customers c JOIN orders o;
```
Без `ON` СУБД делает декартово произведение.

### 2. Неоднозначные имена столбцов
```sql
-- Ошибка: id есть и в customers, и в orders
SELECT id FROM customers c JOIN orders o ON c.id = o.customer_id;
```
**Решение:** указывайте алиас: `c.id` или `o.id`.

### 3. Потеря строк при INNER JOIN
Если нужны все клиенты, а вы используете `INNER JOIN`, клиенты без заказов исчезнут. Используйте `LEFT JOIN`.

### 4. NULL в условии соединения
Если в столбце, по которому соединяете, есть `NULL`, такие строки **не соединятся** даже сами с собой. `NULL = NULL` → `NULL`, а не `TRUE`.

### 5. Дублирование строк при JOIN
Если в правой таблице несколько совпадений, левая строка размножится. Например, у Ивана два заказа → его имя появится дважды. Если нужен уникальный список — используйте `DISTINCT` или `GROUP BY`.

## 🔹 Производительность JOIN

1. **Индексы на столбцах соединения** — критически важны. Обычно это первичный ключ и внешний ключ. Без индексов СУБД делает полный перебор (Nested Loop) — медленно.

2. **Порядок таблиц в JOIN** — оптимизатор обычно сам выбирает лучший порядок, но иногда помогает поставить меньшую таблицу первой.

3. **Фильтры в WHERE vs ON** — для `INNER JOIN` разницы нет. Для `LEFT JOIN` фильтр в `WHERE` по правой таблице превращает соединение в `INNER JOIN` (отсекает NULL-строки). Если нужно сохранить NULL — фильтр должен быть в `ON`:
   ```sql
   -- Сохранит всех клиентов, но покажет только paid-заказы
   SELECT c.name, o.amount
   FROM customers c
   LEFT JOIN orders o ON c.id = o.customer_id AND o.status = 'paid';
   ```

4. **EXPLAIN** — всегда проверяйте план запроса:
   ```sql
   EXPLAIN SELECT c.name, o.amount
   FROM customers c
   JOIN orders o ON c.id = o.customer_id;
   ```
   Ищите `type: ALL` (плохо) или `type: ref/eq_ref` (хорошо).

## ✅ Итог

| Тип | Когда использовать |
|-----|-------------------|
| `INNER JOIN` | Нужны только совпадающие строки (самый частый) |
| `LEFT JOIN` | Нужны все строки левой таблицы, даже без совпадений |
| `RIGHT JOIN` | Редко; обычно переписывают через `LEFT JOIN` |
| `FULL JOIN` | Нужны все строки обеих таблиц (нет в MySQL) |
| `CROSS JOIN` | Генерация всех комбинаций (осторожно!) |
| `SELF JOIN` | Иерархии (сотрудник → руководитель) |

**Главные правила:**
1. Всегда указывайте `ON` — иначе получите декартово произведение.
2. Используйте алиасы (`c`, `o`) для читабельности.
3. Индексируйте столбцы соединения.
4. Для подсчёта связанных записей с `LEFT JOIN` используйте `COUNT(поле_правой_таблицы)`, а не `COUNT(*)`.
5. Проверяйте план запроса через `EXPLAIN`.
