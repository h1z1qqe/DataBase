# Оператор `IN` в SQL — подробный разбор

Оператор `IN` — это логический оператор, который проверяет, **входит ли значение в заданный список**. Он является сокращённой формой цепочки `OR`.

---

## 🔹 Синтаксис

```sql
SELECT столбцы
FROM таблица
WHERE столбец IN (значение1, значение2, значение3, ...);
```

Эквивалентная запись через `OR`:

```sql
SELECT столбцы
FROM таблица
WHERE столбец = значение1
   OR столбец = значение2
   OR столбец = значение3;
```

**Пример из вашего запроса:**

```sql
SELECT * FROM customers WHERE city IN ('Москва', 'Казань');
```

Это то же самое, что:

```sql
SELECT * FROM customers WHERE city = 'Москва' OR city = 'Казань';
```

Результат одинаковый — обе строки вернут клиентов из Москвы и Казани. Но `IN` **короче, читабельнее и удобнее**, особенно если значений много.

---

## 🔹 Как это работает «под капотом»

СУБД выполняет запрос так:

1. Берёт каждую строку таблицы `customers`.
2. Смотрит значение в столбце `city`.
3. Сравнивает его со **всеми** значениями из списка `('Москва', 'Казань')`.
4. Если хотя бы одно совпадение — строка попадает в результат.
5. Если ни одного — строка отбрасывается.

Логически это **дизъюнкция** (логическое «ИЛИ») всех условий.

---

## 🔹 Что можно помещать в список `IN`

### 1. Литералы (константы)

```sql
WHERE city IN ('Москва', 'Казань', 'Новосибирск');
WHERE id IN (1, 2, 5, 10);
WHERE amount IN (100.00, 250.50, 999.99);
WHERE order_date IN ('2026-10-01', '2026-10-05');
```

### 2. Выражения

```sql
WHERE id IN (1 + 1, 3 * 2, 10 - 1);  -- то же, что (2, 6, 9)
```

### 3. Столбцы

```sql
SELECT * FROM orders WHERE customer_id IN (id);  -- сравнение столбцов
```

На практике так почти не пишут, но технически возможно.

### 4. Результат подзапроса (самый мощный вариант)

```sql
SELECT * FROM customers
WHERE id IN (SELECT customer_id FROM orders WHERE amount > 1000);
```

Это вернёт клиентов, у которых есть хотя бы один заказ на сумму больше 1000. Подзапрос выполняется **один раз**, и его результат подставляется в `IN`.

---

## 🔹 `IN` и `NULL` — важный нюанс

`NULL` — это «неизвестное значение». Поэтому:

```sql
WHERE city IN ('Москва', NULL);
```

⚠️ Такое условие **не сработает** для строк, где `city IS NULL`. Потому что `NULL = NULL` возвращает не `TRUE`, а `NULL` (неизвестно). И строка не попадёт в результат.

**Правильно искать NULL отдельно:**

```sql
WHERE city IN ('Москва', 'Казань') OR city IS NULL;
```

Или:

```sql
WHERE COALESCE(city, '') IN ('Москва', 'Казань', '');
```

---

## 🔹 Отрицание: `NOT IN`

Проверяет, что значение **не входит** в список:

```sql
SELECT * FROM customers WHERE city NOT IN ('Москва', 'Казань');
```

Это вернёт всех, кто **не** из Москвы и **не** из Казани.

⚠️ **Ловушка с NULL:** если в списке `NOT IN` есть `NULL`, результат будет **пустым** для всех строк. Потому что `x NOT IN (..., NULL)` всегда даёт `NULL`, а не `TRUE`.

**Пример проблемы:**

```sql
-- Если в таблице есть строка с city = NULL, она НЕ попадёт в результат,
-- потому что NULL NOT IN ('Москва') = NULL (не TRUE)
SELECT * FROM customers WHERE city NOT IN ('Москва');
```

**Решение:** либо избегать `NULL` в списке, либо явно обрабатывать:

```sql
SELECT * FROM customers
WHERE city NOT IN ('Москва') OR city IS NULL;
```

## 🔹 `IN` vs `OR` — когда что использовать

| Критерий | `IN` | `OR` |
|----------|------|------|
| Читабельность | ✅ Лучше при 3+ значениях | ❌ Громоздко |
| Производительность | ✅ Оптимизатор часто обрабатывает лучше | ⚠️ Может быть медленнее |
| Гибкость | Только «равно» | Любые условия (`>`, `<`, `LIKE` и т.д.) |
| Работа с подзапросами | ✅ Да | ❌ Нет |

**Правило:** если у вас цепочка `OR` из одинаковых сравнений `=` — заменяйте на `IN`.

```sql
-- Плохо
WHERE city = 'Москва' OR city = 'Казань' OR city = 'Сочи' OR city = 'Уфа';

-- Хорошо
WHERE city IN ('Москва', 'Казань', 'Сочи', 'Уфа');
```

---

## 🔹 `IN` с несколькими столбцами (row constructor)

Некоторые СУБД (PostgreSQL, MySQL 8.0+) поддерживают сравнение **кортежей**:

```sql
SELECT * FROM orders
WHERE (customer_id, status) IN ((1, 'paid'), (3, 'new'));
```

Это вернёт заказы, где:
- `customer_id = 1` И `status = 'paid'`, **или**
- `customer_id = 3` И `status = 'new'`.

Эквивалент:

```sql
WHERE (customer_id = 1 AND status = 'paid')
   OR (customer_id = 3 AND status = 'new');
```

## 🔹 `IN` и производительность

### Когда `IN` работает быстро
- Столбец проиндексирован (есть индекс на `city`).
- Список значений небольшой (десятки, сотни).
- Подзапрос возвращает немного строк.

### Когда `IN` может тормозить
- Список из тысяч значений — СУБД может не справиться с оптимизацией.
- Подзапрос возвращает миллионы строк — лучше использовать `JOIN` или `EXISTS`.
- Столбец без индекса — будет полный перебор таблицы.

**Проверка плана запроса:**

```sql
EXPLAIN SELECT * FROM customers WHERE city IN ('Москва', 'Казань');
```

В столбце `type` ищите:
- `ALL` — полный перебор (плохо).
- `index` или `range` — используется индекс (хорошо).
- `ref` или `eq_ref` — точечный поиск по индексу (отлично).

---

## 🔹 Альтернативы `IN`

### 1. `EXISTS` — для подзапросов
```sql
SELECT * FROM customers c
WHERE EXISTS (
    SELECT 1 FROM orders o
    WHERE o.customer_id = c.id AND o.amount > 1000
);
```
Часто работает быстрее, чем `IN` с подзапросом, особенно если внешняя таблица большая, а внутренняя — маленькая.

### 2. `JOIN` — если нужны данные из обеих таблиц
```sql
SELECT DISTINCT c.*
FROM customers c
JOIN orders o ON c.id = o.customer_id
WHERE o.amount > 1000;
```

### 3. `BETWEEN` — для диапазонов
```sql
WHERE amount BETWEEN 1000 AND 3000;  -- вместо amount IN (1000, 1001, ..., 3000)
```

### 4. `ANY` / `SOME` — для сравнений с подзапросом
```sql
WHERE amount > ANY (SELECT amount FROM orders WHERE status = 'paid');
```

## 📝 Практические примеры

### Пример 1: Клиенты из нескольких городов
```sql
SELECT name, city FROM customers
WHERE city IN ('Москва', 'Казань', 'Сочи')
ORDER BY city, name;
```

### Пример 2: Заказы с определёнными статусами
```sql
SELECT * FROM orders
WHERE status IN ('paid', 'new')
ORDER BY order_date DESC;
```

### Пример 3: Клиенты, сделавшие заказы на сумму > 1000
```sql
SELECT * FROM customers
WHERE id IN (
    SELECT customer_id FROM orders WHERE amount > 1000
);
```

### Пример 4: Клиенты без заказов
```sql
SELECT * FROM customers
WHERE id NOT IN (
    SELECT customer_id FROM orders WHERE customer_id IS NOT NULL
);
```

Обратите внимание на `WHERE customer_id IS NOT NULL` в подзапросе — это защита от ловушки с `NULL` в `NOT IN`.

### Пример 5: Заказы за конкретные даты
```sql
SELECT * FROM orders
WHERE order_date IN ('2026-10-01', '2026-10-05', '2026-10-10');
```

## ✅ Итог

| Что запомнить | Деталь |
|---------------|--------|
| **Назначение** | Проверка вхождения значения в список |
| **Синтаксис** | `WHERE столбец IN (значение1, значение2, ...)` |
| **Аналог** | Цепочка `OR` с `=` |
| **Подзапросы** | `IN (SELECT ...)` — мощный инструмент |
| **NULL** | `NULL IN (...)` → не `TRUE`; `NOT IN` с `NULL` → пустой результат |
| **Производительность** | Хорошо с индексами и небольшими списками; плохо с тысячами значений |
| **Альтернативы** | `EXISTS`, `JOIN`, `BETWEEN` |

`IN` — один из самых удобных операторов SQL. Он делает запросы короче и понятнее, а с подзапросами становится незаменимым инструментом для фильтрации по связанным данным.

Если хотите, могу разобрать `EXISTS` и сравнить его с `IN` на конкретных примерах — это частая тема на собеседованиях!
